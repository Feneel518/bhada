# Bhadaa

A polished rent-management workspace built with Next.js 16, Tailwind CSS,
Better Auth, Drizzle ORM, Neon Postgres, Google OAuth, and Nodemailer.

## Local setup

```bash
npm install
copy .env.example .env.local
npm run db:push
npm run dev
```

Generate `BETTER_AUTH_SECRET` with at least 32 random characters. The public app
URL must be used for both `BETTER_AUTH_URL` and `NEXT_PUBLIC_APP_URL` in
production.

## Vercel deployment

Add every variable from `.env.example` to the Vercel project. Set
`CRON_SECRET` to a random value of at least 16 characters; Vercel sends it as a
Bearer token when invoking the daily rent-billing route.

The cron in `vercel.json` runs every day at 18:35 UTC (00:05 IST). Apply
the due-day schema update to an existing Bhadaa database before deploying:

```bash
npm run db:add-rent-due-day
```

## Google OAuth

Create a Google OAuth web client and add this authorized redirect URI:

```text
http://localhost:3000/api/auth/callback/google
```

For production, add the same path on the production origin. Then set
`GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.

## Transactional email

Bhadaa sends verification and password-reset messages through Nodemailer. Set:

```env
SMTP_HOST="smtp.example.com"
SMTP_PORT="587"
SMTP_SECURE="false"
SMTP_USER="..."
SMTP_PASS="..."
EMAIL_FROM="Bhadaa <hello@example.com>"
```

Use `SMTP_SECURE=true` for implicit TLS (commonly port 465). Password reset
tokens expire after Better Auth's default one-hour window.

## Plans

| Plan | Price | Limits | Razorpay env var |
| --- | --- | --- | --- |
| One Door | Free | 1 property, 3 units | none |
| Portfolio monthly | ₹49 / month | 5 properties, 25 units | `RAZORPAY_PORTFOLIO_PLAN_ID` (required) |
| Portfolio yearly | ₹499 / year | 5 properties, 25 units | `RAZORPAY_PORTFOLIO_YEARLY_PLAN_ID` |
| Estate | ₹99 / month | 20 properties, 100 units | `RAZORPAY_ESTATE_PLAN_ID` |

Bhadaa is not GST registered, so prices are shown as final with no GST.
Create each optional plan in Razorpay first; it only appears at checkout once
its ID is set. Landlords already on a paid plan can't switch in-app yet.

## Scheduled jobs

- `/api/cron/rent-bills`: daily at 00:05 IST, creates monthly rent bills.
- `/api/cron/daily-summary`: daily at 08:10 IST, emails landlords who have rent
  due today, rent that turned late yesterday, or (on Mondays) anything overdue.

Both run from `vercel.json` on Vercel and from `wrangler.jsonc` triggers on
Cloudflare. Both need `CRON_SECRET`.

## Database migration for this release

`npm run build` runs `scripts/migrate.mjs` first, so every Vercel deploy brings
the database up to date before the new code goes live. It applies 0017–0019
(UPI ID, summary email, billing interval, tenant links, payment claims,
electricity rate, meter readings) with statements that are safe to repeat, and
records them for `drizzle-kit migrate` if that table exists. If the migration
fails, or a production build has no `DATABASE_URL`, the build stops and the
current version stays live. Run it by hand with `npm run db:migrate`.

## Tenant page

Every tenant has a private page at `/t/<token>`. The token is generated by the
database (including for existing tenants) and can be reset from Edit tenant.
Tenants see their balance, bills and receipts, pay by UPI, and tap "I've paid"
with amount, date, method and UTR. That creates a pending claim; nothing changes
in the books until the landlord confirms it on Overview, which records a normal
payment receipt. Landlords get an email for each claim when SMTP is configured.

Tenants can also enter their electricity meter reading (once the unit has an
opening reading). It waits on Overview; Approve creates the bill with the
property's electricity rate (set in Edit property), due 7 days after the
reading. Edit opens the bill form prefilled; Not right sends it back with a note.

## Razorpay Portfolio billing

Create a Razorpay Subscription Plan for ₹49 INR with a monthly billing period,
then configure:

```env
RAZORPAY_KEY_ID="rzp_test_..."
RAZORPAY_KEY_SECRET="..."
RAZORPAY_PORTFOLIO_PLAN_ID="plan_..."
RAZORPAY_WEBHOOK_SECRET="..."
```

Start with Test Mode keys. In Razorpay Dashboard, add this webhook URL:

```text
https://YOUR_DOMAIN/api/billing/razorpay/webhook
```

Subscribe it to all `subscription.*` events, using the same webhook secret set
above. Before enabling live billing, replace the Test Mode key and plan with
their Live Mode equivalents and run the database migration:

```bash
npx drizzle-kit migrate
```

The checkout callback is verified server-side, and renewals, failed charges,
pauses, and cancellations are synchronized through signed webhooks.

## Security model

- `/` is the public marketing page.
- `/dashboard` reads the Better Auth session on the server and redirects guests.
- The dashboard identity comes only from the verified server session.
- Portfolio tables include an `ownerId`; every database read or mutation must
  filter with the current session's `user.id`.
- Email/password accounts must verify their email. Google accounts use Google's
  verified identity.

## Commands

The dashboard includes a guided Property → Unit → Tenant setup. Only the property
name, unit number, tenant name and monthly rent are needed; the due day defaults
to the 1st. Existing properties and vacant units can be reused, and completed
steps are saved immediately. Optional details remain available through Edit.

Overview metrics follow the current collection month (rent bill due dates),
while Payments retains its selected financial year. Income ranges use calendar
year and quarter boundaries. Run the dashboard regression checks with Node 24:

```bash
node --test scripts/dashboard-metrics.test.mjs
```
